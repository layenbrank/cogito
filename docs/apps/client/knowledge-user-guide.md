# Cogito 知识库使用说明（用户向）

理念移植自 [llm_wiki](https://github.com/nashsu/llm_wiki) / Karpathy LLM Wiki 范式。  
本文面向日常使用者；开发实现见同目录 [knowledge.md](./knowledge.md)。

---

## 一句话定位

**Cogito 知识库不是「再开一个笔记本」，而是：你放进尽量不改动的原文，由助手把它们编译成可互相链接、可检索、可持续维护的 Wiki。**

你定方向与取舍；助手负责摄入、交叉引用与日常维护。

---

## A. 和普通笔记有什么本质区别

| 普通笔记 / 文档库 | Cogito 知识库 |
| --- | --- |
| 你自己写、自己整理每一页 | **来源**留作原文；**Wiki** 多由助手整理生成，你再策展 |
| 改一份文件 = 改「那一页」 | **来源尽量当归档，不要当日记本乱改**；要改「认知结论」，改 Wiki 页 |
| 搜索多半是全文搜原文 | 知识**编译进 Wiki 后持续存在**；提问优先走已整理好的页面，不必每次从零「读完所有 PDF」 |
| 很少有「健康检查」 | 有 **Lint**（结构问题）和 **审阅**（需要你拍板的事项） |
| 关联靠你手写标签 | **图谱**看页面如何互相链接；**研究**可往库里补网搜材料 |
| 打开就能写「今天开会了」 | **purpose / schema 不是日记页**——它们是给助手看的「这个库的说明书」（见专章 B） |

### 核心心智模型（流水线）

1. **来源** — PDF、Markdown、剪藏、URL 等（当作不可变原文）
2. **解析 / 入队** — 抽正文，进入左栏底部的 **活动** 队列
3. **摄入（Ingest）** — 助手先理解再写 Wiki 页，并更新目录与概要
4. **Wiki 页面** — 你阅读、编辑、交叉引用（如 `[[页面名]]`）
5. **检索 / 图谱 / 维护** — 查、看关系、跑 Lint、处理审阅、用 AI / 研究补洞

库里长期并存三类东西（下一章细说说明书 vs 内容）：

- **说明书**：`purpose.md`（为什么存在）+ `schema.md`（怎么组织）
- **来源区**：原始资料（导入后尽量少改）
- **Wiki 区**：摘要、实体、概念等百科页（日常阅读与编辑主要在这里）

## B. purpose / schema 专章（必读）

> **先记住一句话：**  
> `purpose.md` 和 `schema.md` **不是日记本、不是待办清单、不是日常笔记页**。  
> 它们是写给助手看的 **「这个知识库的说明书」**：说明这个库要回答什么、收什么、怎么排版与命名。  
> 助手在 **摄入资料、整理 Wiki、回答问题** 时都会参考它们。

### B.1 它们是什么

| 文件 | 一句话 | 回答的问题 |
| --- | --- | --- |
| **purpose.md** | 库的「灵魂 / 方向」 | 这个库为什么存在？给谁用？研究什么？收什么、不收什么？回答时偏严谨还是口语？ |
| **schema.md** | 库的「结构规则」 | Wiki 有哪些页面类型？怎么命名？必须有哪些目录页？交叉引用怎么写？不要乱造什么？ |

建库时系统会自动放两份很短的占位内容，例如：

- purpose：`这个知识库为什么存在？关键问题与研究范围写在这里。`
- schema：`约定 Wiki 结构、frontmatter 与 ingest 规则。由人类与助手共同演进。`

**占位不是成品。** 第一次导入资料前，请改成你自己的说明书（见下方可复制示例）。若一直空着或写成日记，助手会「没有方向地」乱建页、或把闲聊写进 Wiki。

### B.2 和 Wiki 页、来源文件的分工（三者表）

| | **purpose / schema（说明书）** | **来源（原文）** | **Wiki 页面（百科）** |
| --- | --- | --- | --- |
| **写给谁看** | 主要给助手；你偶尔修订 | 归档与核对原文 | 你日常读、改；助手也会写 |
| **该写什么** | 目标、范围、风格、页面类型、命名与引用规则 | 论文、报告、剪藏、PDF 原文 | 概念、人物、摘要、对比、论点 |
| **不该写什么** | 开会流水账、买牛奶、聊天记录 | 你的「整理后的结论」（结论应进 Wiki） | 整份 PDF 原文（原文留在来源） |
| **改的频率** | 建库写一版；主题漂移时再改 | 尽量不改（只增删文件） | 随摄入与策展经常更新 |
| **界面入口** | **设置 → LLM → 打开 purpose.md / schema.md** | 左轨 **来源** | 左轨 **Wiki** |

一句话对照：

- 说明书告诉助手「这座图书馆办什么主题、书架怎么分」；
- 来源是「进馆的书本身」；
- Wiki 是「编目卡片与主题词条」。

### B.3 在界面里怎么打开 / 编辑

逐步操作：

1. 打开 **知识库** 窗口，顶栏选中你要用的库（没有就先「新建知识库」）。
2. 点左侧图标轨最下方的 **设置**（齿轮）。
3. 左侧 Wiki 设置分类里，在 **模型** 分组下点 **LLM**。
4. 右侧会出现说明：「对话 / Ingest 模型走全局 Agent……此处打开 purpose / schema 供助手读取。」
5. 点按钮：
   - **打开 purpose.md**
   - **打开 schema.md**
6. 文件会在编辑器中打开；改完后像普通 Wiki 文档一样保存。

文件落在哪里（通俗说法）：

- 就在**当前知识库的根目录**下，和 Wiki、来源文件夹同级：`purpose.md`、`schema.md`。
- 不必去资源管理器里翻；用上面的两个按钮即可。

模型配置不在这一页：Chat / 摄入用的模型请到 **全局 Agent / 模型设置** 配置（设置页 LLM 区会提示这一点）。

### B.4 purpose 该写什么

建议至少覆盖：

1. **目标读者** — 谁会读这个库的答案？（自己 / 团队 / 某门课）
2. **问题域** — 主要想搞清楚什么？（1～3 个关键问题即可）
3. **收什么 / 不收什么** — 哪些资料值得摄入；哪些明确排除（八卦、一次性日程、无关领域）
4. **回答风格** — 严谨引用来源 / 偏综述 / 偏行动建议；中文还是中英混排
5. （可选）**当前论点** — 你现在的阶段性结论；证据变了再改这一段

#### 可复制短示例 1：个人技术深挖

```markdown
# Purpose

## 目标
为我个人整理「本地优先桌面应用 + AI Agent」相关资料，回答设计取舍，而不是当通用笔记本。

## 关键问题
1. 本地知识库与传统 RAG 各适合什么场景？
2. 摄入（Ingest）流水线里，哪些步骤必须人工策展？
3. 多模态 PDF 解析在什么情况下值得上云端服务？

## 范围
- **收：** 论文、官方文档、高质量技术博文、我自己的实验笔记（先放来源再摄入）
- **不收：** 日常待办、会议流水账、与主题无关的新闻快讯

## 回答风格
- 中文为主；术语可保留英文
- 结论要能指回 Wiki 页或来源；不确定就标明「待核实」
- 不要把闲聊式建议写成「库内事实」
```

#### 可复制短示例 2：读书 / 主题阅读

```markdown
# Purpose

## 目标
跟读《××》，整理人物、主题与情节线索，方便日后复习与引用。

## 关键问题
1. 核心人物的动机与转变是什么？
2. 书中反复出现的主题有哪些，彼此如何对照？
3. 我认同或质疑的论点是什么？

## 范围
- **收：** 本书章节、权威书评、作者访谈
- **不收：** 剧透论坛灌水、与本书无关的其它小说笔记

## 回答风格
- 区分「书中原意」与「我的解读」
- 引用尽量落到章节或 Wiki 人物/主题页
```

### B.5 schema 该写什么

建议至少覆盖：

1. **页面类型** — 例如：资料摘要、实体（人/组织）、概念、对比、综合分析……各放哪类文件夹（可用通俗目录名）
2. **命名约定** — 文件名用中文还是英文短横线？是否「一概念一页」
3. **必须有的索引 / 目录页** — 如 `index`（目录）、`overview`（概要）、`log`（操作记录）由系统维护，你约定「助手更新时要遵守什么」
4. **交叉引用规则** — 优先用 `[[页面名]]`；摘要页要回链到来源；概念页互链相关实体
5. **不要写什么** — 禁止把整份原文粘进 Wiki；禁止无来源的断言；禁止用日记格式建页

#### 可复制短示例 1：通用技术库

```markdown
# Schema

## 页面类型
| 类型 | 放哪里（示意） | 用途 |
| --- | --- | --- |
| 资料摘要 | wiki/sources/ | 每份来源一篇摘要，可追溯原文 |
| 实体 | wiki/entities/ | 产品、组织、人名 |
| 概念 | wiki/concepts/ | 方法、术语、架构模式 |
| 综合 | wiki/synthesis/ | 跨多份来源的对比或结论 |

## 命名
- 一页一主题；文件名用简短中文或英文短横线（如 `本地优先.md` / `local-first.md`）
- 不要用日期当主标题（那是日记，不是词条）

## 必须维护的页
- index：目录，摄入后更新条目
- overview：全局概要，反映当前库状态
- log：简要记录本次摄入做了什么

## 交叉引用
- 正文用 [[页面名]] 互链
- 摘要页须能指回来源文件
- 新概念若与已有页重复，合并或互相 related，不要平行造两个同名页

## 不要
- 不要把 PDF 全文贴进 Wiki
- 不要创建「今日随笔」「待办」类页面
- 没有依据时写「待核实」，不要装成定论
```

#### 可复制短示例 2：读书库

```markdown
# Schema

## 页面类型
- 人物 → wiki/characters/
- 主题 → wiki/themes/
- 情节线 → wiki/plot-threads/
- 章节笔记 → wiki/chapters/
- 资料摘要 → wiki/sources/（书评、访谈等）

## 命名
- 人物页用角色常用名；主题页用短主题名
- 章节页可用 `ch-03-标题关键词`

## 交叉引用
- 人物页链到相关主题与章节
- 主题页列出支撑情节与人物
- 区分「书中事实」与「读者解读」小节

## 不要
- 不要把整章原文复制进 Wiki
- 不要用 schema/purpose 记读后感流水账（读后感可建独立 Wiki 页，如「我的解读-第3章」）
```

### B.6 反例：这些绝对不要写进 purpose / schema

| 错误写法 | 为什么错 | 应该写到哪里 |
| --- | --- | --- |
| 「今天开会了，张三说下周上线……」 | 这是**事件流水账**，不是库的目标或结构规则 | 若值得沉淀：建 Wiki 页（如会议结论摘要），或放其它笔记工具；原文纪要可进**来源**再摄入 |
| 「待办：买牛奶 / 回复邮件」 | 说明书不是待办本；会污染助手对「库主题」的理解 | 用日历 / 待办 App；**不要**写进知识库说明书，一般也不该进 Wiki |
| 在 schema 里写长篇读后感 | schema 只约定结构；感想是内容 | 单独 Wiki 页，或先当来源 Markdown 再摄入 |
| 把 purpose 当天日记不断追加 | 助手每次都会读到过时噪音，摄入方向飘 | purpose 只保留**稳定方向**；日记另存 |
| 直接改 `raw/sources` 里的 PDF「当笔记改」 | 来源应尽量不可变；改原文会搞乱追溯 | 改 Wiki；或新增一份来源，而不是覆盖旧文件 |

**口诀：**  
说明书里只写「这座库怎么办」；「今天发生了什么」要么进来源、要么进 Wiki 词条，要么根本不进这个库。

### B.7 什么时候改 purpose / schema

| 时机 | 要不要改 | 说明 |
| --- | --- | --- |
| **刚建库** | **要** | 写一版可用的目的与结构（可先短后长） |
| **主题明显漂移** | **要** | 例如从「读书」变成「竞品调研」——更新范围与页面类型 |
| **发现助手乱建页 / 风格不对** | **要** | 在 schema 写清禁止项；在 purpose 写清风格 |
| **每天写日记式追加** | **不要** | 会把说明书变成噪音 |
| **每摄入一篇就改一次** | **通常不要** | 摄入应遵循现有说明书；规则稳定优于频繁改 |

### B.8 改完后对摄入 / AI 有什么影响

通俗理解：

- 下次助手 **整理新来源（摄入）**、**回答你的问题**、**做研究补洞** 时，会按**新说明书**来判断：该不该收、建成什么类型的页、怎么命名与互链、回答偏什么语气。
- **不会**自动把过去已经写好的全部 Wiki 按新规则重写一遍；旧页仍在。若结构大变，你可能需要：删改明显不合规的页、跑 **Lint / 审阅**、必要时对重要来源再摄入或手动策展。
- 所以：**先写清 purpose / schema，再大量导入**，比「先堆一百份 PDF 再补说明书」省事得多。

## C. 从入门到日常（逐步到按钮级）

### C.1 建库

1. 打开应用中的 **知识库**。
2. 左轨点 **Wiki**（书本图标），看左栏顶上的库选择框。
3. 点旁边的 **+**（「新建知识库」）。
4. 输入名称 → 回车或点 **建**。
5. 确认当前选中的是新建的库。

首次会自动带上 purpose / schema 占位和空的 Wiki 目录页——请立刻进入 B.3 改说明书。

### C.2 先写 purpose / schema（强烈建议在导入前完成）

1. 左轨底 → **设置**
2. **模型 → LLM**
3. **打开 purpose.md** → 按 B.4 写好 → 保存
4. **打开 schema.md** → 按 B.5 写好 → 保存

### C.3 配模型（全局）

1. 知识库设置里的 LLM 页**只负责打开说明书**，不在这里填 API Key。
2. 到应用的 **全局 Agent / 模型设置**，配置可用的对话模型（摄入与问答都依赖它）。
3. 回到知识库；若活动队列出现 **阻塞**，多半是模型 / 助手未就绪——配好后在 **活动** 里解除阻塞或重试。

### C.4 导入来源

1. 左轨点 **来源**。
2. 使用顶栏按钮：
   - **导入文件** — 选 PDF、Markdown 等
   - **文件夹** — 整夹导入（目录结构可帮助分类）
   - **URL** — 抓取网页（注意仅适合可公开访问的地址；一次数量有上限）
   - **刷新** — 重新扫描来源列表
3. 导入后通常会自动进入摄入队列（若开启了自动摄入相关选项）。

**原则：** 来源是归档。不要把「来源」当可随意涂改的日记本。

### C.5 看活动（摄入进度）

1. 看左栏**底部活动条**（排队 / 处理中 / 失败 / 阻塞 / 完成）。
2. 可暂停、继续、取消、对失败项 **重试**，对阻塞项在模型就绪后 **解除阻塞**。
3. 处理完成后，到 **Wiki** 查看新生成的页面与目录更新。

### C.6 读、改 Wiki

1. 左轨 **Wiki** → 在文档列表点开页面。
2. 中间编辑器阅读与修改；需要大纲时，用窗口标题栏打开右栏 **大纲**。
3. 可用 `[[页面名]]` 做交叉引用（与 schema 约定一致最好）。
4. 左栏 **生成**：让助手按主题直接写一篇新 Wiki（仍应符合 purpose / schema）。

系统维护的目录 / 概要 / 日志页（如 index、overview、log）会随摄入更新；你主要策展实体、概念、摘要等内容页。

### C.7 检索

1. 左轨 **检索**，输入关键词。
2. 点开命中结果跳到对应页。
3. （可选）在 **设置 → Embedding** 开启向量检索：默认关闭；开启后需配置兼容的向量接口。多数情况先用全文检索即可。

### C.8 图谱

1. 左轨 **图谱**。
2. 查看页面如何通过链接互相关联；点击节点打开对应页。
3. 用图谱发现「孤立页」「薄弱区域」，再决定补资料或跑研究。

### C.9 Lint（健康检查）

1. 左轨 **Lint** → **运行 Lint**。
2. 查看断链、结构问题等；按提示修复（例如为断链创建占位页）。
3. 建议在大批量摄入后、或改完 schema 想整顿结构时跑一次。

### C.10 审阅

1. 左轨 **审阅**。
2. 处理摄入时助手标出的「需要你拍板」的项（创建页 / 跳过 / 触发后续研究等，以界面操作为准）。
3. 不必卡住摄入：审阅可以稍后集中处理。

### C.11 研究（深度研究）

1. 窗口标题栏点开 **研究**（右栏会切到研究页签）；或从右栏 tabs 选 **研究**。
2. 用于知识空白：按主题做网络检索，结果可再进入来源 / Wiki 流水线。
3. 使用前在 **设置 → 网页搜索** 配置可用的搜索服务；需要本地全文时可看 **AnyTXT**（Windows）。

### C.12 AI 助手

1. 标题栏打开 **AI**（或右栏 **AI** 页签）。
2. 就当前库提问、让助手根据 Wiki / 来源作答、协助改写选区等。
3. 有价值的回答若要长期保留：整理成 Wiki 页（或按产品提供的「存回 wiki」类能力归档），而不是只留在聊天记录里。

### C.13 设置里常用项（通俗）

左轨 **设置**，左侧分类概览：

| 分类 | 你可以调什么 |
| --- | --- |
| **LLM** | 打开 purpose / schema（说明书） |
| **Embedding** | 可选向量检索（默认关） |
| **多模态** | 是否给资料中的图片生成说明 |
| **网页搜索** | 深度研究用的搜索服务 |
| **AnyTXT** | 本机全文检索通道（Windows） |
| **网络** | 代理等出站设置 |
| **API / Clip** | 本机剪藏与对外只读查询开关、Token、是否允许局域网 |
| **源监听** | 监视来源文件夹变更并自动入队；多库时后台先记着，打开对应库再处理 |
| **定时导入** | 定期从指定目录扫入来源 |
| **MinerU / PDF** | 复杂 PDF 用哪种解析方式（内置 / 旁路 md / MinerU 等） |
| **输出** | Wiki 生成语言等 |
| **维护** | 重建索引、导出、清空摄入队列、扫描重复、补强链接等 |

## D. 推荐工作流 + 常见坑

### D.1 推荐工作流（对齐 llm_wiki，用 Cogito 按钮名）

1. **建库** → 立刻写好 **purpose / schema**
2. **全局配好模型**
3. **来源** 导入少量高价值资料（先少后多）
4. 盯 **活动** 至完成 → 在 **Wiki** 抽查摘要与链接是否符合 schema
5. 处理 **审阅**；需要时跑 **Lint**
6. 用 **检索 / 图谱 / AI** 使用知识；空洞处用 **研究** 补材料再摄入
7. 主题变了再修订说明书；不要天天改

### D.2 特别强调（用户最容易踩的坑）

1. **别把 purpose / schema 当普通笔记**  
   不写开会记录、不写待办、不写「今天……」。只写库的目标与结构规则。

2. **别把来源当可涂改日记**  
   来源是原文归档。要改结论 → 改 Wiki；要补充 → 新增来源文件。

3. **日常碎记怎么办？**  
   - 值得进知识体系：建**独立 Wiki 页**（符合 schema 的类型），或先保存为来源再摄入。  
   - 纯生活琐事：用其它笔记 / 待办工具，**不要污染说明书与原文归档**。

4. **先堆资料、后补说明书**  
   助手前期会缺乏方向，页面又杂又难清理。先说明书，再批量导入。

5. **活动一直阻塞**  
   检查全局模型 / 助手是否可用，再在活动里解除阻塞或重试。

6. **复杂 PDF 解析不对**  
   到 **设置 → MinerU / PDF** 确认后端；不是只填了地址却仍走默认轻量解析。

7. **改完 purpose/schema 期望旧库自动重排**  
   新规则主要影响**之后**的摄入与问答；旧页需人工或再次整理。

8. **向量没开就以为「坏了」**  
   默认关闭 Embedding；全文检索 + Wiki 编译是主路径。

### D.3 自检清单（第一次用完勾一下）

- [ ] 已建库并选中正确库
- [ ] purpose 写清了目标、范围、风格（不是日记）
- [ ] schema 写清了页面类型、命名、引用、禁止项
- [ ] 全局模型可用
- [ ] 导入了至少一份来源且活动显示完成
- [ ] 在 Wiki 里能看到摘要或概念页
- [ ] 知道审阅 / Lint 入口
- [ ] 知道日常碎记不该写进 purpose / schema / 来源原文
