# 业务错误码说明

HTTP 状态码表达「这次调用在协议语义上是否成功」，响应体 `code` 表达「业务语义为何失败」；
两者由 `code::http_status` 统一推导，业务结果一律以 `code` 为准（见 [api-versioning.md](api-versioning.md)）。

## 编码规则（XXYYZZ）

| 段位 | 含义 |
|------|------|
| XX | 模块代码 |
| YY | 功能代码 |
| ZZ | 错误序号 |

## 常用状态码

| code | 含义 |
|------|------|
| 200000 | 成功 |
| 200001 | 缺少参数 |
| 200002 | 参数格式错误 |
| 200003 | 参数值无效 |
| 200005 | 请求频率过高（Auth IP 限流） |
| 300001 | 用户未登录 |
| 300002 | 凭证无效 |
| 300003 | Token 过期 |
| 300006 | 权限不足 |
| 400001 | 资源不存在 |
| 500101 | 用户不存在 |
| 500102 | 用户名已存在 |
| 500201 | 不支持的文件类型 |
| 500204 | 文件不存在 |
| 500207 | 上传会话不存在或已结束 |
| 500301 | 登录凭证无效 |
| 500105 | 密码强度不够 |
| 500305 | 密码重置失败 |
| 500401 | 支付订单不存在 |
| 500402 | 支付订单已关闭 |
| 500403 | 支付订单已过期 |
| 500404 | 支付金额与订单不一致 |
| 500405 | 支付渠道不可用 |
| 500406 | 支付签名校验失败 |
| 500407 | 支付渠道返回错误 |
| 500408 | 档位不可购买（未定价 / 缺配额 / 需走支付） |
| 600001 | 数据库错误 |
| 700001 | 数据不一致 |

完整定义见 [`src/utils/code.rs`](../src/utils/code.rs)。

## Apifox 断言建议

断言 `body.code === 200000`，不要断言 HTTP 状态码（状态码只表达协议语义，见上）。

## 开发环境字段

`ApiErrorResponse.details` 仅在开发环境返回，生产环境不包含此字段。
