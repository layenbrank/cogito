# cogito 桌面端：右栏终端稳定、代码页卡死治理、composer 队列与 chip 线格式（方案 B）

## 概述

这一轮把四件互相牵连的事放在一起收口，因为它们共用同一条上游症状：**渲染进程主线程被不可中断的工作占住**。

1. **右栏终端启动不稳 / 空白**：`terminal-view.tsx` 在 `await resolveTerminalTypeface()`（无超时，可能要读几 MB Nerd Font）之后才创建 xterm —— 字体链一卡就永久白屏；`bootstrapTerminalSessions()` 被 5 处并发调用互相覆盖状态；终端视图随页签卸载重建，画面完全依赖 PTY replay。
2. **代码页进入即卡死**：任何文件树刷新都会 `forced` 重灌 TypeScript 库（`packTypes` 过 IPC + `setExtraLibs` 全量替换 → TS worker 重建 program）；首屏把恢复的所有 tab 全文读进内存；递归 watch 在 JS 侧才过滤 `node_modules`，且树刷新与 git 刷新共用同一个 350ms 定时器。
3. **composer 队列**：assistant-ui local runtime 的队列只在内存里，只有「立即发送 / 删除」，没有「修改」，刷新即丢。库的 `QueueItemState` 只暴露 `move / remove`，没有 `edit`。
4. **composer chip**：线格式是 assistant-ui 的 directive（`:file[chat.tsx]{name=apps/...}`），与 Cursor 的 `@apps/...` 不一致；且 `Enter` 分支误用了 Backspace 的整块删除逻辑 —— `@` 选完按回车 = 删 chip 且不发送；粘贴把 chip 文本当字面量。

chip 采用**方案 B**：`serializeDocument` 只写 `@<id>`，`parseDocument` 只认 `@`。**不做兼容性代码** —— 不保留 directive 解析分支、不写迁移脚本，旧格式文本从此按普通文本显示。性能部分按「VS Code 是怎么不卡的」逐条对齐：语言服务相关内容移出交互关键路径（按项目指纹惰性注入、只增删变化的 `.d.ts`）、树刷新与 git 刷新解耦节流、编辑器模型按需创建、monaco 入口从「全语言」瘦到「按需注册」、长任务可观测。

影响面：`packages/design/src/assistant/`（composer 三件套 + 单测）、`apps/client/src/features/terminal/`、`apps/client/src/views/agent/chat/`、`apps/client/src/views/code/`、`apps/client/src/features/agent/`、`apps/client/src/lib/`、`apps/client/src/hooks/use-through.ts`、`apps/client/src/features/agent/model/prompts.ts`、`apps/client/vite.chunk.ts`。

### VS Code 的做法与本项目落差（性能部分依据）

| VS Code | 我们 | 本计划动作 |
| --- | --- | --- |
| TS/JS 语言服务在独立 worker/进程（`tsserver`），主线程只发请求、只收可见范围诊断（`onlyVisible`） | 已在 worker，但 `setExtraLibs` / `setCompilerOptions` 是主线程 API，且触发 worker 全量重建 | 指纹缓存 + 只对**变化**的 `.d.ts` 做 `addExtraLib` / `dispose`；配置先比 JSON 指纹 |
| `ProjectService` 按项目惰性建 program，`@types` 由 TS 自己从磁盘解析 | Monaco 无 fs，只能注入 | 注入一次长期有效，树刷新不再重灌；仅 tsconfig 指纹变化或换工作区才重来 |
| `files.watcherExclude` 在内核 watcher 层排除 `**/node_modules/**`、`**/.git/**` | 排除在 JS 里做，事件已过桥 | 先量化事件速率；确为瓶颈再单开一轮改 Tauri 侧 |
| 树刷新与 SCM 刷新是两条可合并的独立服务 | 一个 350ms 定时器同时打两枪 | 拆成两条节流链 + 可见性门控 |
| 编辑器模型按需创建、不可见即释放（`ModelService`） | 首屏把所有 tab 全文读进来 | 首屏只读 active tab，其余按需（MonacoHost 已有惰性读路径） |
| 启动期非关键工作走 idle（`IdleValue` / `RunOnceScheduler`） | 全部 `useEffect` 立即执行 | 新增 `lib/perf/idle.ts`，把 packTypes、树 bump、git refresh 排到 idle |
| 语言功能按语言惰性激活（contribution 按需） | monaco 根入口全量 | 改 `editor.api` 入口 + 按扩展名注册 basic-language |
| 慢事件循环有 `EditorPerformanceReporter` / timer 记录 | 无 | `PerformanceObserver({type:'longtask'})` + dev 日志 + 计数暴露 |

## 方案

### 1. chip 线格式（方案 B）

| chip 类型 | 线格式 | 例子 |
| --- | --- | --- |
| 文件 / 文件夹 | `@<id>`（id 即引用路径，分隔符统一 `/`） | `@apps/client/src/views/agent/chat/chat.tsx` |
| 含空格的路径 | `@"<id>"`（引号包裹，内部 `"` → `\"`） | `@"apps/my dir/a.ts"` |
| 浏览器标签页 | `@browser-<uuid>`（用 UUID 正则确认前缀） | `@browser-fc893ce2-4290-416f-b07b-78ae4a992e40` |
| 技能 | `@skill:<name>` | `@skill:dingtalk-aitable` |
| 旧 directive | **不识别**（不做兼容） | `:browser[页面标题]{name=browser-2}` 只剩普通文本 |

- **往返恒等**：`serialize(buildChip(x)) === '@' + id`；parse 后 id 完全相同，label 由 `deriveChipLabel(type, id)` 派生（file/dir → id；browser → id；skill → 去掉 `skill:`）。「光标 offset = 序列化长度」这条不变式不变，`locateOffset / sliceAtoms / replaceRange` 不用动。
- **不误伤**：`@` 必须落在 token 边界（行首 / 空白 / `（`、`，`、`、`、`"`、`'`），且 id 需满足「含 `/`」或「匹配 `browser-<uuid>`」或「`skill:` 前缀」；否则当普通文本。`user@example.com`、`@Component()`、`@media` 都不会变 chip；极端情况下被当 chip 也无损（线格式文本恒等，只是视觉上是 chip）。
- **type 推断**：`browser-` + UUID → `browser`；`skill:` 前缀 → `skill`；否则 `file`。线格式不再需要 type 字段。
- **label 不进线格式**：浏览器 chip 的页标题由视图层可选注入（实时查 browser store），取不到就显示 id。
- **prompts 同步**：`prompts.ts:92` 改为「文本形如 `@browser-<uuid>`，去掉前导 `@` 后就是 tab 参数」，并补一句文件引用是 `@相对路径`。

### 2. 性能治理取舍

| 方案 | 取舍 |
| --- | --- |
| A. 保持每次树刷新全量重灌 TS，只加防抖 | 改动最小，但保存一次仍重建 program，`@types/node` 越大越慢；不解决根因 |
| B. 指纹缓存 + `addExtraLib` 增量 + 只在内容变化时动 | **选它**。与 VS Code「program 按项目惰性、lib 变更才 reload」同构，改动局限在 `monaco-types.ts` 内部 |
| C. 不注入 `@types/node`，让用户配 `typeRoots` 指磁盘 | Monaco 无 fs 访问权，只能改走完整 LSP，代价过大 |
| D. 关掉 TS 语义检查换启动速度 | 诊断消失，用户会认为编辑器坏了 |
| E. 首屏仍恢复所有 tab 全文 | 实测最像「进页面就无响应」；改成只读 active、其余按需 |

### 3. 队列编辑（库无 `edit`）

| 方案 | 取舍 |
| --- | --- |
| 原地编辑（直接改队列项文本） | 库没暴露 `edit`，要 patch store，属于私有 API 依赖 |
| **取回式编辑**：`remove` 当前项 + `setText` 回输入框（对齐 VS Code Copilot Chat） | 只用公开 API，语义清晰；代价是队列顺序需要重新 send 回来 |
| 只做持久化、不做编辑 | 不满足需求 |

选**取回式**，并把队列按 `threadID` 落库（新建 `apps/client/src/features/agent/composer-queue.ts`），reconcile 策略：会话仍在运行时逐条 `setText` + `send({ steer: false })` 复原；已结束的会话把条目渲染成自定义「待发送」条，等用户手动触发。

## 实施步骤

### 1. 终端先出壳，字体后台升级

`apps/client/src/features/terminal/terminal-view.tsx`：mount effect 里**同步**创建 `XtermTerminal`（用 `FALLBACK_FONT_FAMILY` + 默认字号）并立刻 `open(container)`，再起 `void refreshTypeface()` 后台升级 —— `terminal.options.fontFamily = ...` 不需要重建实例。`terminal-font.ts` 的 `resolveTerminalTypeface` 外面包 `Promise.race`（约 1500ms 超时，超时直接用兜底值并 `warn`），`document.fonts.ready` 不再作为主路径的阻塞点。验证：断网/塞一个超大的假字体文件启动终端，xterm 立即出现光标，字体在就绪后替换。

### 2. 终端会话生命周期：单飞 + 常驻 + fit 重试

`apps/client/src/features/terminal/agent-tabs.ts`：`bootstrapTerminalSessions` 加 `inFlight: Promise<BootstrapResult> | null` 与 `generation` 计数，并发调用复用同一个 Promise、过期结果直接丢弃；`hydrateSession` 不再把 `exited: true` 翻回 `false`（保留退出态，只补 `pid`）；`restoreAgentPanel` 加 `onlyIfHidden` 参数，已有 `activeId` 时不抢。`terminal-tabs.tsx` 改为「最近 N 个 tab 常驻挂载、非 active 用 `opacity-0 pointer-events-none` 保活」（N 建议 4，LRU），切页签不再重建；`terminal-layout.ts` 去掉 `LAYOUT_ATTEMPTS = 60` 的放弃逻辑，改为「每次 ResizeObserver 回调都尝试 fit，尺寸为 0 就保持 pending」。验证：连点页签 10 次 + 折叠再展开面板，终端画面始终不被清空，`attach` 次数不随点击增长。

### 3. chip 线格式内核（方案 B）

`packages/design/src/assistant/composer-document.ts`：`buildChip:65` 的 `serialized` 改为 `` `@${needsQuote(id) ? `"${escape(id)}"` : id}` ``；`parseDocument:107` 整体改为 `scanMentionTokens`（边界 + 形态启发式 + 引号）扫描，**不再调用 `defaultDirectiveFormatter`**、不保留 directive 分支，`@assistant-ui/react` 在这处的依赖一并删掉；新增 `deriveChipLabel(type, id)` 与 `findAtomStartingAt(atoms, offset)`（Delete 用，与 `findAtomEndingAt:213` 对称）。同时重写文件头注释（去掉「复用 defaultDirectiveFormatter、prompts 不用改」的旧结论）。验证：`pnpm --filter @cogito/design exec vitest run src/assistant/composer-document.test.ts` 全绿（用例期望值按新格式改，并补 `@path` / 引号路径 / `@browser-<uuid>` / `@skill:x` 四组往返用例，外加一条「旧 directive 文本不产生 chip」的断言）。

### 4. chip 视图与消费端

`composer-input.aui.tsx:118` 的 `renderChip` 拆两段：`data-slot="chip-dir"` 显示目录部分（`min-w-0 truncate`）、`data-slot="chip-base"` 显示末段（`shrink-0`），得到「…/src/chat.tsx」式中段省略，`title` 仍是全路径；`composer-chip-text.tsx:38` 同步结构并给 `ComposerChipText` 加可选 `resolveLabel?: (type, id) => string | undefined`，`thread.aui.tsx` 里 `UserTextPart` 注入浏览器 store 查标题；`composer-triggers.tsx` 的 mention `onSelect` 把 `label` 改为引用路径本身，skill 段改为 `insertChip({ type:'skill', label: name, id: \`skill:${name}\` })`；`prompts.ts:92` 改文案。验证：`pnpm --filter @cogito/design type-check` + `pnpm --filter @cogito/client type-check`；新消息里的 `@path` 渲染成 chip，旧消息里的 `:type[...]` 按普通文本显示。

### 5. 键位、剪贴板与 `@` 面板

## 数据库改动（无迁移文件，零 ALTER）

**结论**：本轮不需要改动任何「已经在使用」的表。队列用独立新表承载，因此没有 `ALTER TABLE`、没有列增删、没有表重建，`agent_session` / `agent_message` 等既有数据一行不动。

| 方案 | 取舍 |
| --- | --- |
| A. `ALTER TABLE agent_session ADD COLUMN queue TEXT`（队列整段存 JSON） | 少一张表，但每写一条队列都要 `UPDATE` 会话整行；一条 JSON 写坏就整队丢失；且仍然是改在用表 |
| B. 新表 `agent_composer_queue`（**选它**） | 行级增删改、天然有序（`lane` + `sort`）、会话删除级联清理；零 ALTER |

表结构与可执行 SQL 见 [`.cogito/plans/cogito-composer-queue-2026-11-05.sql`](./cogito-composer-queue-2026-11-05.sql)：

```sql
CREATE TABLE IF NOT EXISTS agent_composer_queue (
    id          TEXT    PRIMARY KEY NOT NULL,
    sessionID   TEXT    NOT NULL,
    lane        TEXT    NOT NULL DEFAULT 'main',   -- main | steer
    sort        INTEGER NOT NULL DEFAULT 0,
    text        TEXT    NOT NULL,                  -- 线格式文本（chip 已 @ 序列化）
    attachments TEXT    NOT NULL DEFAULT '[]',
    "createdAt" INTEGER NOT NULL,
    "updatedAt" INTEGER NOT NULL,
    FOREIGN KEY (sessionID) REFERENCES agent_session (id) ON DELETE CASCADE
);
CREATE INDEX IF NOT EXISTS idx_agent_composer_queue_sessionID
    ON agent_composer_queue (sessionID, lane, sort);
```

**DDL 单源与两条执行路径**（沿用仓库既有 `agent_plan_schema.rs` + `migration::ensure_agent_plan()` 的模式，**不新增 0002 迁移文件**）：

- 新增 `apps/client/src-tauri/crates/database/src/migrations/composer_queue_schema.rs`，`statements()` 返回上面两段幂等语句。
- 新库：`migrations_0001.rs` 末尾调用 `composer_queue_schema::statements()`，并在 `migrations/mod.rs` 注册模块。
- 老库：`migration.rs::run()` 追加 `ensure_composer_queue()`（与 `ensure_agent_plan()` 同构，启动时 `IF NOT EXISTS` 兜底）。
- 新 entity `entity/agent_composer_queue.rs`（`AgentComposerQueueEntity`），并加入 `migration::tests::entity_columns_match_ddl` 的清单，保证 entity 与 DDL 不漂移。
- 手工 SQL 文件：`.cogito/plans/cogito-composer-queue-2026-11-05.sql`，幂等，可立即对本地库执行（不想等下次启动、或想先自己确认时用）。

**旧消息内容不做重写**：`agent_message.content` 里的 `:file[...]{name=...}` 是纯文本，而 SQLite 没有正则替换，用 `replace/instr` 拼只会在「多 chip、多类型混排」时写坏。按「不做兼容性代码」的约定，本轮不提供改写脚本 —— 数据不丢，只是那段文字不再有 chip 外观。将来若要补，单独写一次性 Rust/Node 脚本读 `content` → 替换 → 回写，比 SQL 可靠。

**执行与自检**：先完全退出应用 → 备份 `cogito-client.db`、`-wal`、`-shm` → 跑 SQL → 执行文件末尾 4 条自检（表存在、列齐、`session`/`message` 计数与执行前一致、`migrations` 里仍只有 `0001`）。

## 风险与待确认

- **不做兼容的现实代价**：历史消息与旧草稿里的 `:file[...]{name=...}` 从此按普通文本显示，没有 chip 外观、没有 `title`、点不动；编辑旧消息回填时同样是裸文本。这是本轮明确接受的取舍（不留分支、不写迁移脚本），但要写进发布说明，避免被当成新 bug 报回来。
- **`@` 变语义标记的溢出**：用户可能真发含 `@media` / `user@example.com` / `@Component` 的代码。启发式能挡绝大多数，且误判时线格式文本恒等（模型无损）。**待确认**：是否接受偶尔的视觉误判，还是要「只有 @ 面板插入过的 id 才算 chip」（后者跨会话不可靠，建议不做）。
- **`skill:` 前缀占用**：skill chip 的 id 从「相对路径」变成 `skill:<name>`，relative 不再进线格式。**待确认**：有没有别处依赖 chip 的 skill id 定位技能文件（当前只做 tooltip）。
- **浏览器 chip 标题会降级**：线格式只有 uuid，标题靠视图层实时查 store；标签页关掉后只能显示 uuid。
- **`monaco-types` 增量注入**依赖 `addExtraLib` 的 handle 台账。**待确认**：handle 在 `setCompilerOptions` 之后是否仍有效（无效则退化为「配置变化时全量重建 libs」）。
- **`registerTabWithoutContent` 的连带假设**：`requestCloseTabs` / dirty 判定 / `monaco-models.findModel` 是否假设 model 必然存在。**待确认**：保存路径在「tab 无 model」时的行为。
- **递归 watch 的 exclude 只能在 Tauri 侧做**：`@tauri-apps/plugin-fs` 的 `watch` 只有 `recursive/delayMs`。本轮先量化（每秒事件数），若确为瓶颈再单开一轮改 `apps/client/src-tauri`。
- **monaco 入口瘦身有回归面**：`editor.api` 不含全部语言与贡献，可能「某语言不高亮」「某命令缺失」。因此放在最后、可单独回滚，并以 build 体积 + 四语言高亮作为验收。
- **面板等宽依赖 Root 无左右 padding**：若 `ComposerPrimitive.Root` 有 `px-*`，`inset-x-0` 会贴到 padding 外沿，需要 `-mx-5 sm:-mx-6` 补偿；实施时先量 `getBoundingClientRect()`。
- **队列落库**：已定为本地 SQLite 的同库新表 `agent_composer_queue`（见「数据库改动」一节），**不新增迁移文件、不改在用表**。代价是渲染进程不能直接写 SQLite，必须多一对 Tauri 命令（`toRead` / `toReplace`），`toReplace` 要用事务保证「删旧 + 插新」原子。
- **性能目标用代理指标**：长任务条数、IPC 频次、`readCodeFile` 次数、`[monaco-types]` 日志次数，不做帧率断言。
