## 二、三个必须补的缺口

### 缺口 A（P0）：`bridge` token 也在渲染进程里，而且比 serve token 更狠

**证据链**：

- `bridge/http.rs:30` 的 `BridgeInfo { url, token }` 经 `bridge:info` 返回前端；
- `features/agent/acp/session.ts:302-315` 把它注入 MCP server 的 `env`（`COGITO_BRIDGE_URL` / `COGITO_BRIDGE_TOKEN`）；
- `crates/mcp/src/main.rs:33-36` 从 env 读 token，之后每个 `/internal/tools/call` 都带它（`bridge/http.rs:93` 鉴权）；
- 这个 token 之上挂着 `app_terminal_run`（任意命令执行）、`app_browser_act`、`app_knowledge_write_doc` 等**全部工具**。

也就是说：**渲染进程被拿下，等于拿到"以用户身份执行任意命令"的能力**——这比 serve token（只能操控一次 agent 会话）严重得多，而我的 S2 完全没提。

**改法**（并入 S2，改名"令牌不出进程"）：

1. Rust 启动后把 bridge token 原子写到 `<appLocalData>/bridge/token`（Windows 设 DACL、Unix 0600，仅当前用户）；
2. `BridgeInfo` 去掉 `token`，只回 `{ url, mcpPath, tokenFile }`；
3. `session.ts` 注入的 env 改为 `COGITO_BRIDGE_TOKEN_FILE`；
4. `cogito-mcp` 支持从文件读（`main.rs` 的 `Bridge::from_env` 加一条分支），保留 env 作为兼容；
5. 顺手把 token 和 `COGITO_SESSION_ID` 绑定校验（`bridge/http.rs` 的 `authorize` 增加 session 头），避免一个 token 被复用到别的会话。

**验收**：`rg "COGITO_BRIDGE_TOKEN" apps/client/src` 只剩 Rust 侧；MCP 全工具 e2e 通过；杀掉前端重连后工具仍可用。

### 缺口 B（P0）：agent 的"写"不走 `app_*`，我把 deny 规则放错了层

这是上一版计划里最实质的错误。取证：

- `agent-tools.lock.json` 的 local 面里**只有读**（`app_workspace_list` / `app_workspace_read`），没有写；
- `approval.ts:174-208` 明确把 goose 的 `text_editor` / `str_replace` 当写工具；
- `workspaceFilesReplace`（`workspaceFiles.rs:1610`）是**代码窗的"全部替换"**在用，不是 agent 的路径。

推论有两条，都很关键：

1. 我原打算把 deny 放进 `resolve_under_roots:172` —— 那会**同时废掉用户自己在编辑器里的替换/保存**（用户操作不算越权），属于误伤；
2. 就算放进去，**也拦不住 agent**：agent 写文件用的是 goose 内置 `text_editor`，压根不经过 `workspaceFiles.rs`。

**改法**（S3 重写为两步）：

- **B1 给 agent 一个受控写工具**：新增 `app_workspace_write` / `app_workspace_patch`（Rust，`crates/core/src/tools/workspace.rs`），复用 workspace 根校验 + 新增 deny 表 + 写前快照（供 diff 卡复用）；同时把 goose developer 扩展里的文件/命令工具全部 `never_allow`（`approval.ts:250` 的机制已具备，只需把名单扩到 `text_editor` / `str_replace` / `apply_patch`）。
- **B2 deny 只放在 agent 入口**：规则落在 `crates/core/src/tools/*`（工具层），`workspaceFiles.rs` 保持服务 UI；若希望 UI 也提示，加显式参数 `strict: true`，默认 `false`。
- **HARD/SOFT 的归属也要改**：`.git/` 写入 = HARD（agent 永久拒）；`.env` / `*.pem` = SOFT（agent 需每次确认，UI 不拦）。

**验收**：模型调 `text_editor` 被拒；`app_workspace_write` 写 `.git/hooks/pre-commit` 被拒、写 `.env` 触发 SOFT；代码窗"全部替换"仍能改 `.env`（证明没误伤用户）。
